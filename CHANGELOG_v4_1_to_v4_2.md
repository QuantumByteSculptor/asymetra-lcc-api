## Root Cause of v4.1 Contradictions

The v4.1 report (`generate_v3_report.py`) loaded its ML metrics from
`data/metrics/train_v3_report.json`, which was generated by a broken evaluation
run and contained corrupted data (n=50, single-fold duplicated metrics).

The **correct** source is `models/v3/v3_metrics.json`, generated at training time
from the actual model + 5 real validation folds. v4.2 uses this source exclusively.

### [FIX-7] Generator enforces consistency guards at startup

`generate_credibility_v4_2.py` aborts with exit code 2 if any of the following
invariants are violated:
1. `t_lo == t_hi` (threshold sanity)
2. fold_5 n in `v3_metrics.json` != fold_5 n in `splits_manifest.json`
3. fold_5 ROC-AUC < 0.65 (regression detector)
4. aggregate ROC-AUC mean < 0.60 (wrong-file detector)
5. fold_5 n == 50 (corrupted-data detector)

This prevents a recurrence of the v4.1 data-source bug.
